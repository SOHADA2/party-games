# 숙소에서 하기 좋은 게임 모음

친구들과 숙소(펜션·MT)에서 하는 오프라인 게임의 **진행·순위 도구**.
게임 자체는 현실에서 하고, 폰은 방 코드 접속 · 역할 뽑기 · 순위 · 종합 리더보드만 담당한다.

## 실행

**Node 18+ 만 있으면 된다.** 설치할 의존성도, 빌드도, 환경변수도 없다.

```bash
git clone https://github.com/SOHADA2/party-games.git
cd party-games
node serve.mjs        # http://localhost:8080
node serve.mjs 8123   # 포트 지정
```

같은 와이파이의 폰에서는 서버가 알려주는 `http://<PC IP>:포트` 로 접속.
⚠️ `file://` 로 직접 열면 서비스워커·일부 기능이 동작하지 않는다. 반드시 http로.

## 검증 (커밋 전)

```bash
node tools/check.mjs                                    # 문법 + 끊어진 참조, 실패 시 exit 1
node tools/demo.mjs tools/scenarios/smoke-e2e.js _s.html
node tools/shot.mjs --dom "/_s.html?demo=1"             # 게임 6종 + 백본 자동 점검
rm -f _*.html                                           # 검증 사본 정리
```

`tools/demo.mjs` 는 Firebase의 `set/update/remove` 를 스텁으로 바꾼 사본을 만든다 —
검증하다가 **실제 방이 만들어지는 사고**를 막기 위한 것이다.
자세한 절차와 함정은 `CLAUDE.md` 의 「검증 레시피」 참고.

## 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 전체 (단일 파일, 빌드 없음) |
| `manifest.json` / `icon.svg` | PWA — 홈 화면에 추가 시 앱처럼 실행 |
| `sw.js` | 앱 셸 캐시 (network-first + 오프라인 폴백) |
| `serve.mjs` | 로컬 테스트 서버 |
| `tools/` | 검증 도구 (문법 검사 · 검증 사본 생성 · 헤드리스 스크린샷) |

## 동기화 모델 — 호스트가 진실원

방 코드로 여러 폰이 접속하지만, **점수·팀·순번의 기준은 호스트(진행자) 기기**다.

- 호스트: 로컬 상태를 고치고 즉시 렌더 → Firebase RTDB에 write-through (실패해도 무시).
  서버 스냅샷에서는 `players`(다른 사람 입장)만 병합해서 받는다.
- 참가자: 서버 스냅샷을 그대로 반영. 자기 `players/{pid}` 노드만 쓴다.

→ **숙소 인터넷이 끊겨도 호스트 화면에서 게임 진행·점수 입력이 그대로 되고,
복구되면 다음 쓰기 때 전체 권위 필드를 다시 밀어 자동으로 맞춰진다.**

## 데이터

Firebase RTDB (aram 프로젝트 재사용, `party` 노드로 격리)

```
/party/rooms/{4자리코드}
  createdAt, touchedAt, host, status
  players/{pid}   : { name, joinedAt, seen }      // seen = 20초 하트비트
  teams           : { count, assign:{pid:팀번호} }
  scores/{sid}    : { gameId, mode, order[], weight, assign, at }
  rotation/{게임id}: [pid...]                      // 이미 술래/출제자 한 사람
```

`order`는 순위 배열(개인전=pid, 팀전=팀 인덱스). 점수는 저장하지 않고 **매번 계산**해서
배점을 바꾸면 과거 기록에도 즉시 반영된다. 팀전 기록은 그 시점 `assign`을 스냅샷으로 함께 저장하므로
나중에 팀을 다시 짜도 과거 점수가 깨지지 않는다.

12시간 이상 손대지 않은 방 코드는 재사용된다.

## 점수

```
1등 10 · 2등 7 · 3등 5 · 4등 3 · 5등 2 · 이하 1
× 게임별 배점(weight)
팀전 = 팀 순위 점수를 팀원 전원에게 동일 지급
```

## 게임 추가하기

`index.html` 의 `GAMES` 배열에 항목 하나만 추가하면 목록·규칙·역할 뽑기·순위 입력·리더보드에
전부 자동 반영된다.

```js
{
  id:'newgame',            // 고유 id (점수 기록의 키)
  name:'게임 이름',
  emoji:'🎲',
  mode:'solo' | 'team',
  weight:1,                // 배점 배수
  role:'술래' | null,      // 있으면 중복 방지 랜덤 뽑기 UI 표시
  tag:'술래 1명',          // 목록에 뜨는 한 줄 설명
  rules:`...`,             // <b> 태그 사용 가능
  todo:'미확정 규칙 메모'   // (선택) 앱에 경고 박스로 표시
}
```

## 현재 상태

**게임 7종**, 전부 전용 진행 도구까지 구현 —
멕썸노이즈 · 스마일~! · 초성 퀴즈 · **노래 맞히기** · 몸으로/한글자로 말해요 · 연기 대결 · 컵 레이스.

⚠️ **노래 맞히기만 인터넷이 필요합니다.** 유튜브 뮤직은 웹페이지에 임베드가 막혀 있어
(`X-Frame-Options`), 재생은 진행자 폰의 유튜브 뮤직에 맡기고 앱은 문제·정답·점수만 맡습니다.
백본(방 생성/참여, 팀 랜덤, 술래 뽑기, 순위 입력, 종합 리더보드, PWA, 화면 꺼짐 방지)도 완료.

**태블릿은 「사회자」로 방에 들어간다**(v0.15.0) — 대기실에서 기기 하나를 「사회자(화면)」로
지정하면 팀·술래 뽑기·순위·리더보드에서 빠진다. 태블릿이 선수로 세어져 팀이 홀수로 갈리는 걸 막는다.
게임은 **개인전 / 팀전**으로 묶이고, 「누가 폰을 잡는가」는 게임 상세에 따로 표시된다.

**태블릿 1대를 가운데 두고 다 같이 본다**(v0.14.0) — 넓은 화면에서는 방 코드·타이머·순위처럼
「다 같이 보는 것」이 화면을 꽉 채운다. 반대로 몸으로 말해요의 제시어처럼 **한 사람만 봐야 하는
정보는 커지지 않는다**(`.priv`) — 공용 화면에서 커지면 그 판이 그냥 끝나기 때문.

**규칙이 단순한 게임만 남긴다**(v0.13.0) — 크라임씬(추리 상황극)과 「안 봤어도 들키지마」는
설명에만 몇 분이 걸려 숙소에서 바로 시작하기 어려웠다. 대신 규칙 한 줄로 시작되는
게임들로 채운다. 새 게임은 `GAMES` 배열에 한 항목만 추가하면 앱 전체에 반영된다.

남은 것: 간단한 게임 추가, 실기기 테스트.
